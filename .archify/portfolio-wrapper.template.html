2. ROS 2 Node Communication Architecture

TOPIC: Publisher → Subscriber · ACTION: Client → Server(응답·피드백은 역방향) · PYTHON/OBJECT: 같은 Isaac 프로세스 안의 관계. 그림의 Python object는 독립 ROS 노드가 아닙니다.

* PickPlace 호출은 simulate_p3020=false일 때 사용합니다. arrival_confirm 대기는 manual_delivery=true일 때 적용됩니다.
† map→base_link는 TF 체인 조회이며, IW Hub Graph 하나가 전체 변환을 발행한다고 확정하지 않습니다.
‡ Nav2–Graph는 기능 수준의 연결입니다. 실제 토픽 remap과 TF broadcaster는 외부 설정·실행 중 ROS 그래프로 확인해야 합니다.

상세도는 MQTT와 HTTP 전송을 생략하고 ROS 메시지·Isaac 내부 관계에 집중합니다. System Architecture에는 React가 Vision 서버에서 직접 읽는 IN/OUT MJPEG 경로가 포함됩니다. AMR/Top View 영상 노드와 보조 디버그 토픽은 이 뷰의 범위 밖입니다.

현재 Mission 경로의 비전은 IN/OUT detector입니다. 저장소의 LocateBox legacy service/relay는 별도 경로이며, 활성 기본 미션 연결로 합치지 않았습니다.
