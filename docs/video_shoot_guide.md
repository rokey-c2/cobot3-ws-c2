# 데모 영상 촬영 가이드

데모 마감: 2026-08-28 · 목표 길이: 약 65~75초

> 이 문서는 **촬영/편집 실무용**입니다. 왜 이렇게 결정했는지에 대한 논의 과정이 궁금하면
> `docs/video_storyboard_plan.md`를 참고하세요. 여기서는 "무엇을, 어떤 순서로, 어떻게
> 찍을지"만 다룹니다.

---

## 1. 컨셉 한 줄

> 물류센터 자동화는 반복 작업은 잘 처리하지만, **우선순위 변경 같은 예외 상황은 결국
> 사람이 판단해야 한다.** 기존엔 사무실 담당자가 현장에 **전화로 요청**해야 했다면,
> 우리 시스템은 **웹으로 바로 원격 조작**할 수 있다 — 그 차이를 보여주는 영상.

**연출 컨셉 (2026-08-27 확정)**: CCTV 하드컷. 물리 장면들을 CCTV 화면 느낌(그레인,
타임스탬프 오버레이)으로 하나씩 하드컷으로 보여준 뒤, **줌아웃하면서 그게 사실 웹 관제
UI 안의 CCTV 패널들이었다는 걸 리빌**하는 구조. "우리가 방금 본 모든 장면이 실시간으로
관제되고 있었다"는 걸 설명 없이 한 번에 증명하는 장치.

**업데이트 (2026-08-27 저녁)**: CCTV 패널을 편집 합성이 아니라 **실제 라이브 스트리밍
4채널로 구현하기로 확정**. Isaac Sim에 고정 카메라 4대(Top View / AMR / 로봇팔 / 소터)를
배치해서 각각 ROS2 토픽으로 발행하고, 웹 대시보드가 그걸 실시간으로 받아서 보여줍니다.
구현 스펙은 별도 문서 `docs/cctv_streaming_spec.md`에 있고, **이 컴퓨터가 아니라 Isaac
Sim 담당 컴퓨터와 웹 담당 컴퓨터에서 각각 진행 중**입니다. 아래 3장의 "실기능 vs 합성"
서술은 이 업데이트 이전 내용이니, 최신 상태는 3장 하단의 갱신 노트를 보세요.

## 2. 전체 구성

| # | 장면 | 목표 길이 | 성격 |
|---|---|---|---|
| 1 | 오프닝 와이드샷 | 3~5초 | 실물 촬영 |
| 2 | CCTV 하드컷 몽타주 (AMR → 로봇팔 → 소터) | ~12초 | 실물 촬영 + CCTV 필터(그레인/타임스탬프) |
| 3 | **리빌**: 줌아웃 — 방금 그 화면들이 웹 관제 UI의 CCTV 패널이었음 | ~5초 | 편집 합성 (아래 3장 참고) |
| 4 | 웹 관제(Control Tower) — 긴급 대응 시나리오 | ~18~20초 | 실물+합성 혼합 (아래 4장 참고) |
| 5 | 마무리 와이드샷 | 3~5초 | 실물 촬영 |

**순서 이유**: 2번(하드컷 몽타주)으로 "현장이 자동으로 잘 돌아간다"를 빠르게 보여준 뒤,
3번(리빌)에서 "근데 이걸 웹에서 다 보고 있었다"로 반전을 주고, 4번(관제 대응)에서
"그리고 필요하면 바로 개입도 한다"로 마무리하는 구성. 관제 파트를 앞이 아니라 뒤에
둬야 임팩트와 여운이 큽니다.

## 3. CCTV 하드컷 + 리빌 (2번·3번 장면)

### 2번 — CCTV 하드컷 몽타주

- AMR 자율주행(박스 팔레트 이동) → 로봇팔 Pick & Place → 휠 소터 분류, 이 세 장면을
  **각각 짧게(2~4초씩) 하드컷**으로 붙임.
- 편집 필터로 CCTV 느낌 추가: 그레인, 타임스탬프 텍스트(예: `CAM 01 · 09:42:17`),
  살짝 낮은 프레임레이트/노이즈 느낌.
- 각 장면 촬영 방법은 기존과 동일:
  - **AMR**: 카메라를 AMR 근처에 두고 박스 실린 팔레트 이동 촬영. 실행은
    `./scripts/run_isaac_mission.sh` → `./scripts/run_ros2.sh` → `./scripts/run_pose_sync.sh`
    → 미션 트리거(README "전체 통합 미션" 순서).
  - **로봇팔**: P3020이 박스를 컨베이어에 올리는 장면. 이미 검증된 경로, 추가 준비 불필요.
  - **소터**: 이 장면은 **별도 브랜치의 소터 전용 데모**를 따로 실행해서 찍습니다(1~2번과
    같은 실행이 아님). 지금 메인 시나리오는 박스 1개만 흐르기 때문에 "여러 박스가 각자
    다른 곳으로 분류되는" 그림이 안 나와서입니다.
    ```bash
    git checkout hwi_new_sorter   # 또는 origin/hwi_new_sorter를 별도로 체크아웃
    # Isaac Sim에서 isaac_sim/sorter_demo.py 실행
    # → 2초 간격으로 박스가 계속 랜덤 스폰되며 트랙 01/02/03으로 자동 분류됨
    ```
    같은 소터 로직(코드)을 쓰는 격리된 테스트 씬이라 내용상 문제는 없음.
  - **자막/나레이션 주의**: "카메라가 인식해서 분류한다"처럼 표현하지 말 것 — 실제로는
    박스가 생성될 때 이미 정해진 값(사전 할당) 기준으로 분류됩니다. "박스마다 정해진
    목적지로 정확히 분류된다" 정도로 표현.

### 3번 — 리빌 (줌아웃)

- 방금 본 CCTV 화면들이 실은 **웹 Control Tower 대시보드 안의 카메라 패널**이었다는 걸
  줌아웃으로 드러내는 컷.
- **최신 결정 (2026-08-27 저녁 갱신)**: 4채널 전부 실제 라이브 스트리밍으로 구현
  확정 — Top View / AMR / 로봇팔 / 소터, 총 4대. 구현 세부사항(토픽명 `cctv_0`~`cctv_3`,
  해상도, 브리지 서버 등)은 `docs/cctv_streaming_spec.md`에 있고, Isaac Sim 쪽과 웹 쪽을
  각각 별도 컴퓨터/에이전트가 나눠서 진행 중입니다. 이 문서(촬영 가이드)에서는 결과물만
  다룹니다.
  - `cctv_0`(Top View)은 기존 몽타주(2번)에는 없던 **새 앵글**입니다 — 리빌 컷에서
    "맵 전체를 내려다보는 조감 패널"까지 4칸으로 보여주면 관제실 느낌이 더 살아납니다.
  - 나머지 3칸(AMR/로봇팔/소터)은 2번 몽타주에서 찍은 것과 같은 구간을 비추는 실시간
    피드입니다.
- **폴백(구현이 촬영 전까지 안 끝날 경우)**: 원래 계획대로 안 되는 채널만 편집 합성으로
  대체합니다 — 대시보드 스크린샷 위에 2번에서 찍은 클립을 해당 패널 자리에 얹고 줌아웃
  무빙을 편집으로 만드는 방식. 화면상으로는 실기능/합성이 구분되지 않으니 일부만
  합성이어도 시청자 입장에선 문제 없습니다. **촬영 전날 반드시 4채널 각각 실제로
  뜨는지 확인하고, 안 되는 채널만 이 폴백으로 전환하세요.**

## 4. 웹 관제 (4번 장면, 가장 중요)

**배경 서사**: 사무실에서 업무 중인 담당자에게 "긴급 배송 요청" 알림이 옴 → 노트북으로
확인 → AMR을 수동으로 우선순위 위치로 보내고, 컨베이어를 재가동 → 물류센터 정상 처리.

**디바이스 (2026-08-27 갱신: 태블릿 → 노트북)**: 실제 관제 조작 환경이 마우스 기반
노트북/데스크톱이라 노트북 쪽이 더 사실적이고, 노트북은 프론트엔드가 반응형이 아닌 문제
(아래 "왜 화면은 합성인지" 참고)도 애초에 없어서 목업 합성 자체가 불필요해짐. "옆에 두고
있다가 알림 받는다"는 상황은 노트북 화면에 알림이 뜨는 걸로 동일하게 표현.

**장소**: 사무실 (카페보다 신뢰도 있는 톤).

| 컷 | 내용 | 실기능 / 연출 |
|---|---|---|
| 4-1 | 담당자가 업무 중, 옆 노트북 화면 켜짐 → 알림 클로즈업: **"긴급 배송 요청 접수 — B구역 우선 처리"** | 연출 (실제 알림 시스템 없음, 자막/그래픽 합성) |
| 4-2 | 노트북에서 브라우저로 대시보드 진입 (3번 리빌에서 봤던 그 화면과 같은 UI) | **실기능** — 정상 크기 화면 그대로 녹화, 목업 합성 불필요 (노트북이라 반응형 문제 자체가 없음) |
| 4-3 | AMR을 수동조작(Jog)으로 우선순위 위치로 이동 | **실기능** — 실제 버튼을 눌러 조작, 진짜로 AMR이 움직임 |
| 4-4 | 컨베이어 상태 확인(STOPPED, 빨강) → START 탭 → RUNNING(초록)으로 바뀜 | **실기능** — 진짜 클릭, 진짜 상태 변화 |
| 4-5 | 물류센터 와이드샷: 정상 처리 재개 (= 5번 마무리 샷과 이어짐) | 실물 촬영 |

**참고 (노트북으로 확정된 이유)**: 관제 웹페이지는 화면 최소 폭이 1180px로 고정돼 있어서
태블릿에 그대로 띄우면 레이아웃이 깨졌음 — 그래서 원래는 노트북/모니터에서 녹화한 화면을
편집 때 태블릿 그래픽 안에 합성하는 방식을 썼는데, 애초에 노트북으로 촬영하면 이 문제
자체가 없어서 목업 합성 과정 없이 화면 녹화본을 그대로 쓰면 됩니다. 조작과 반응은
100% 진짜입니다.

**"3중 매칭" 연출 포인트**: ①노트북 알림 문구의 구역명(예: B구역) = ②대시보드 화면 속
같은 구역명 = ③물류센터 실물 화면 속 그 구역. 이 세 곳을 같은 이름으로 맞춰서
매치컷하면, "지금 이 순간 실제 상황을 보고 있다"는 게 설명 없이 눈으로 증명됩니다.

**화면 프레이밍 시 반드시 넣을 것**: 브라우저 주소창(URL 바)이 보이게 프레이밍.
이게 있어야 "이건 전용 앱이 아니라 웹"이라는 게 자막 없이 전달됩니다.

## 6. 자막/나레이션에서 피해야 할 표현

| 쓰면 안 되는 표현 | 이유 | 대신 쓸 표현 |
|---|---|---|
| "카메라가 보고 판단해서 분류한다" | 실제로는 사전 할당된 값 기준, 실시간 비전 판단 아님 | "박스마다 정해진 목적지로 정확히 분류된다" |
| "AI가 이상을 감지해서 알림을 보낸다" | 실제 알림/이상감지 시스템 없음 (연출) | 알림 내용 자체를 담당자 업무 맥락으로만 자연스럽게 제시, 시스템 기능이라고 명시하지 않기 |
| "즉시 자동으로 복구된다" (4번 장면) | 실제로는 사람이 수동으로 조작해서 복구하는 장면 | "담당자가 원격으로 즉시 조치한다" |
| "이 CCTV들은 전부 실시간이다" (일부 채널이 폴백으로 합성 처리된 경우에만 해당) | 구현이 늦어져 일부 채널만 편집 합성으로 대체했다면, 그 사실이 맞지 않음 | 굳이 구분해서 설명하지 않음 — 화면상 구분 안 되므로 언급 자체를 피함 |

## 7. 이 영상이 보여주려는 것 (요약)

1. **2~3번**: 자동화 파이프라인이 실제로 끝까지 잘 돌고, 그걸 웹에서 실시간으로 다 보고
   있다 (AMR→로봇팔→소터, CCTV 리빌).
2. **4번**: 그 위에서, 예외 상황이 생기면 사람이 사무실에서 웹으로 바로 개입할 수 있다
   — 전화도, 현장 이동도 필요 없이.

이 두 가지가 합쳐져서 "자동화 + 실시간 관제 + 필요할 때 사람이 개입하는 하이브리드
제어"라는 프로젝트의 핵심 메시지를 완성합니다.
