# 영상 제작 AI 브리프 (Shot Spec)

작성일: 2026-08-27 (최신화)
기반 문서: `docs/video_shoot_guide.md` (촬영/편집 실무 최신안), `docs/cctv_streaming_spec.md`
(실시간 CCTV 스트리밍 구현 스펙 — 별도 세션에서 진행 중)
용도: 영상 생성/편집 AI 툴에 그대로 입력하기 위한 스펙 문서. 논의 과정/평가 기준 등
맥락 정보는 전부 제외하고 실행에 필요한 스펙만 담음.

> **디바이스 확정 (2026-08-27)**: 태블릿이 아니라 **노트북**으로 확정됨. 실제 관제 조작
> 환경이 마우스 기반 노트북/데스크톱이고, 노트북은 프론트엔드 반응형 미지원 문제(최소
> 폭 1180px)도 없어 목업 프레임 합성이 필요 없어짐. `docs/video_shoot_guide.md`의 "태블릿"
> 서술은 이 결정 이전 내용이니 그쪽도 갱신 필요.

## ⚠️ 중요 제약사항 (반드시 지킬 것)

**판단 기준**: 이 장면이 "시스템이 실제로 작동하는 모습"을 보여주는가?

- **YES (실촬영 표시)** → 이 프로젝트는 실제 시뮬레이션·실제 웹 대시보드가 작동하는지를
  평가받는 디지털 트윈 데모다. 로봇/창고/컨베이어/소터가 나오는 장면, 웹 대시보드가 실제
  조작에 반응하는 장면은 **AI로 새로 생성하거나 대체하지 말 것.** 반드시 실제 Isaac Sim
  녹화본/실제 웹페이지 녹화본을 사용한다.
- **NO (MOCKUP/서사 표시)** → 시스템 기능과 무관한 순수 서사·인물 연출 장면(사무실 인물,
  알림 그래픽)은 **AI 생성 허용**. 실제 배우가 촬영해도 되고 AI로 만들어도 됨.
- **CONDITIONAL (리빌 샷, Scene 3)** → `docs/cctv_streaming_spec.md`의 4채널 실시간
  스트리밍이 촬영 전까지 완성되면 **실촬영**(진짜 라이브 피드), 안 되면 **합성 폴백**
  (대시보드 스크린샷 위에 Scene 2 클립을 패널 자리에 얹고 줌아웃 무빙 편집). 촬영 전날
  4채널이 실제로 뜨는지 확인 후 이 문서의 해당 항목 라벨을 확정할 것.
- 나레이션 음성 없음, 자막/캡션 없음. **단, CCTV 타임스탬프 오버레이(`CAM 0N · HH:MM:SS`
  형식)는 자막이 아니라 화면 안 진단용 UI 텍스트라 허용됨** (아래 스타일 가이드 참고).

## 전역 스타일 가이드

```
Look: CCTV / 보안카메라 몽타주 (Scene 2, Scene 3)
- Grain: 있음 (노이즈/약간 낮은 프레임레이트 느낌)
- Timestamp overlay: 화면 좌상단 또는 우상단, "CAM 0N · HH:MM:SS" 형식 텍스트
  (N = 01/02/03, 1번=AMR, 2번=로봇팔, 3번=소터 — 서사용 자막 아님, CCTV UI 요소로 허용)
- Cut style: 하드컷만 사용, 디졸브/크로스페이드 금지
- Camera: 모든 샷 고정(static, locked-off), 팬/줌 없음 (Scene 3 리빌만 예외 — 줌아웃 1회)
- Aspect ratio: 16:9
- Resolution: 1920x1080
- Audio: 없음 (무음 또는 배경음만, 나레이션 금지)
- Text overlay: CCTV 타임스탬프 외 없음 (알림 문구 자체는 Scene 4-1 그래픽의 일부, 자막 아님)
```

## 샷별 스펙

| ID | 소스 | 길이 | 카메라 | 내용 | 비고 |
|---|---|---|---|---|---|
| Scene 1 | 실촬영(SIM) | 3~5s | static wide | 물류센터 전체 공정 오프닝 와이드샷 | |
| Scene 2-a | 실촬영(SIM) + CCTV 필터 | 2~4s | static, CAM 01 | AMR이 박스 팔레트 싣고 자율주행 | 그레인+타임스탬프 오버레이 |
| Scene 2-b | 실촬영(SIM) + CCTV 필터 | 2~4s | static, CAM 02 | 로봇팔이 박스를 컨베이어에 적재 | 그레인+타임스탬프 오버레이 |
| Scene 2-c | 실촬영(SIM, `sorter_demo.py` 별도 실행) + CCTV 필터 | 2~4s | static, CAM 03 | 컨베이어 위 박스들이 트랙별로 분류됨 | 소스 촬영은 30~40s 넉넉히, 트리밍해서 사용 |
| Scene 3 | **조건부** (실촬영 or 합성, 위 제약사항 참고) | ~5s | 줌아웃(고정→줌아웃 1회) | 방금 본 CCTV 화면들이 사실 웹 대시보드 안의 라이브 카메라 패널(Top View/AMR/ARM/SORTER 4분할)이었다는 리빌 | 4채널 스트리밍 완성 여부에 따라 라벨 확정 |
| Scene 4-1a | **MOCKUP** | 1~2s | medium shot | 사무실, 담당자가 다른 업무 중 → 옆 노트북 화면에 알림 켜짐 | 서사 연출. AI 생성 또는 실배우 촬영 |
| Scene 4-1b | **MOCKUP** | 1~2s | close-up | 알림 그래픽 클로즈업: "긴급 배송 요청 접수 — B구역 우선 처리" | 서사 연출. AI 생성 또는 그래픽 목업 |
| Scene 4-2 | 실촬영(웹) | 2~3s | static, 화면 그대로 사용 (합성 불필요) | 노트북 브라우저에서 주소창이 보이는 채로 대시보드 진입 (Scene 3에서 본 그 UI) | 노트북이라 목업 합성 불필요. 태블릿으로 되돌리면 이 항목만 "웹 녹화→기기 프레임 합성"으로 수정 |
| Scene 4-3 | 실촬영(SIM) | 3~4s | static | AMR이 담당자 수동조작(Jog)으로 우선순위 위치까지 이동 | |
| Scene 4-4 | 실촬영(웹) | 3~4s | static, 화면 녹화 | 컨베이어 상태가 STOPPED(빨강)→RUNNING(초록) | |
| Scene 5 (= 4-5) | 실촬영(SIM) | 3~5s | static wide | 물류센터 와이드샷, 정상 흐름으로 복귀 (클로징) | |

편집 순서: Scene 1 → 2-a → 2-b → 2-c → 3 → 4-1a → 4-1b → 4-2 → 4-3 → 4-4 → 5 (전부 하드컷)

## 연출 장치 — 3중 매칭 (일관성 체크리스트)

Scene 4-1b의 구역명, Scene 4-2에서 보이는 대시보드 화면 속 구역명, Scene 5의 와이드샷에서
강조되는 구역 위치가 **동일한 이름/동일한 위치**로 일치해야 함.

## 톤 — 쓰면 안 되는 표현 (자막을 쓰게 되거나 나레이션 스크립트를 짤 경우)

| 금지 표현 | 이유 | 대체 표현 |
|---|---|---|
| "카메라가 보고 판단해서 분류한다" | 실제로는 사전 할당된 값 기준 분류, 실시간 비전 판단 아님 | "박스마다 정해진 목적지로 정확히 분류된다" |
| "AI가 이상을 감지해서 알림을 보낸다" | 실제 알림/이상감지 시스템 없음 (연출) | 시스템 기능이라고 명시하지 않고 업무 맥락으로만 제시 |
| "즉시 자동으로 복구된다" (Scene 4) | 실제로는 사람이 수동 조작해서 복구 | "담당자가 원격으로 즉시 조치한다" |
| "이 CCTV들은 전부 실시간이다" (일부가 합성 폴백일 경우) | 사실과 다를 수 있음 | 화면상 구분 안 되므로 언급 자체를 피함 |

## 출력 스펙

```
Container: mp4 (H.264)
Resolution: 1920x1080
Frame rate: 실촬영 소스와 동일하게 맞춤 (권장 30fps)
Total duration target: 65~75초
Audio track: 없음
```
